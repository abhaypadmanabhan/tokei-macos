## Findings

S1 [should] AIUsageDashboard/scripts/perf-bench.sh:109 Each benchmark run leaves a `ai.padzy.tokei.perf.<uuid>.plist` in the REAL `~/Library/Preferences`. `CFFIXED_USER_HOME` moves Foundation paths, but cfprefsd still writes the per-bundle defaults domain under the real user's home. The app writes `provider_hidden_*`, `notificationThresholdFiredKeys` and `tokei.onboarding.seeded.v1` there. The `finally` (line 192) cleans up only the temp tree, so AC1's "synthetic home" isolation leaks into the real Library on every run, and the files pile up. It does not touch the installed app's own domain, because the bundle id differs. Repro: `ls ~/Library/Preferences | grep -c tokei.perf` -> `4`. Two of them are this lane's reported runs: `...c82a6bc4...` (baseline) and `...711b213f...` (final). `defaults read` on one shows the keys above. Fix: in `finally`, after the child exits, run `defaults delete <identity>` and unlink `<real home>/Library/Preferences/<identity>.plist`. Get the real home from `pwd.getpwuid(os.getuid()).pw_dir`, because `HOME` is synthetic only for the child. Also delete the four existing leftovers once (orchestrator's call).

S2 [nit] AIUsageDashboard/AIUsageDashboardApp/Core/Sync/SyncEngine.swift:118 Providers with no watched folder (Cursor `state.vscdb`, opencode, Gemini, Antigravity state DB) used to refresh incidentally on every other provider's file event, roughly every 10 s while any agent wrote. Now they refresh only on the 300 s periodic, a manual refresh, or the dashboard window's `.task` refresh. Opening the popover flushes only pending file providers (`visibilityChanged`), so the popover can show these providers up to 300 s stale. AC2 asks for exactly this, and the old freshness was accidental. Reading. Fix (optional): have the popover's hidden-to-visible transition also run one `refreshAll()` if the last full refresh is older than about 15 s.

S3 [nit] AIUsageDashboard/AIUsageDashboardApp/Core/Utilities/FileWatcher.swift:150 `stop()` now clears `pendingPaths`. `refreshWatchPaths()` calls `stop()` and then `start()` whenever the root set changes, and a targeted refresh calls `refreshWatchPaths()` first. A batch still pending for another provider is therefore dropped, and that provider waits for its next write or the 300 s periodic. Before this branch the same drop happened, but the refresh in progress was always full, so nothing went stale. This only bites when a new root appears (first Copilot/Antigravity run, a new `.claude-*`/`.codex-*` profile). Reading. Fix: in `refreshWatchPaths`, if `batchID != nil`, emit the pending batch, or mark it `requiresFullRescan`, before `stop()`.

S4 [nit] AIUsageDashboard/AIUsageDashboardApp/Core/Utilities/FileWatcher.swift:180 `affectedProviders` resolves symlinks on every root once per event path (paths x roots `resolvingSymlinksInPath`, each one several lstat calls). That cost now matters because `kFSEventStreamCreateFlagFileEvents` sends one path per file write. Resolve `watchedURLs` once per call, or cache them when the roots change. There is also a quirk: `resolvingSymlinksInPath` strips `/private` only for paths that still exist, so under `/private/var` a deleted file maps to no root and causes a full refresh. That is conservative, and real homes under `/Users` are not affected. Reading.

S5 [nit] AIUsageDashboard/AIUsageDashboardApp/Core/Providers/ClaudeCodeProvider.swift:359 The failed-probe cadence applies to every refresh, not only file-event refreshes. After `missingCredentials`/`expiredCredentials`/`unauthorized`, the user follows the warning copy ("Run `claude` once, then try again"), but manual Refresh keeps showing the cached failure for up to 600 s. Other failures are mostly hidden by the client's stale-cache fallback. Cutting `security` spawns for API-key users (no OAuth item) is the right intent. Reading. Fix (optional): key the failure on the credential source's fingerprint, or let a user-initiated refresh clear `failedQuotaAttempts`. Otherwise accept and note the 10-minute recovery lag.

S6 [nit] AIUsageDashboard/AIUsageDashboardApp/Core/Parsing/SQLiteSidecarCopy.swift:18 `fingerprint` uses `LocalUsageFileFingerprint.read`, which `lstat`s and requires `S_IFREG`. A symlinked Antigravity `state.vscdb` now fails every refresh with "could not be read", where the SQLite backup used to follow the link. The `-wal` exists-then-lstat check also races SQLite deleting the WAL on last close, which gives a one-refresh warning. The new struct also duplicates `AntigravityConversationFiles.Fingerprint` (database+wal). Reading. Fix: resolve symlinks first, as Cline does (`url.resolvingSymlinksInPath()`), and treat ENOENT on a sidecar as nil.

S7 [nit] AIUsageDashboard/AIUsageDashboardApp/Core/Network/AntigravityQuotaClient.swift:95 Between attempts, live windows are reused only if every window has a non-nil future `resetAt`. A live reading with a nil `resetAt` falls through to `loadStaleCache()`, so a reading under 300 s old is served as stale for up to 5 minutes. Reading. Fix: reuse `lastLiveWindows` when `resetAt` is nil or still in the future.

S8 [nit] SyncEngine.swift:215 Under actor reentrancy, two `drainFileEvents` calls (the scheduled task and an event or visibility change) can each call `scheduleFileRefresh` after their `await refresh(...)`. The second overwrites `fileRefreshTask` without cancelling the first. The result is a harmless extra drain, not a lost or duplicated refresh. Fix: `fileRefreshTask?.cancel()` inside `scheduleFileRefresh`.

S9 [nit] AIUsageDashboard/scripts/perf-budget.json:3 The CPU budget (5%) passes the old code by 3x (baseline 1.583%), so the harness cannot catch this lane's win regressing. The budget was set before the baseline, so it was not tuned to pass. Separately, "footprint does not grow" rests on one run each (80.374 vs 79.970 MB mean), while the author's own repeat of the final build measured 64.6 MB. The 0.4 MB difference is well inside run-to-run noise, so AC7's memory half is "no evidence of growth", not a measured hold. The CPU claim follows from the two outputs: (1.583-0.439)/1.583 = 72.27%, confirmed by the repeat at 0.410%. Fix (optional, later): tighten CPU to about 1% after merge, and report a median of 3 runs for footprint.

## Checked and fine
- AC2 mapping: component-bounded prefix match, shared ancestors map to all providers, unknown roots or dropped/MustScanSubDirs/RootChanged flags fall back to a full refresh. Rename/rotation events carry paths under the root. Profile and env-override roots map correctly.
- Coalescing: `refresh(providers:)` unions into pending state before joining the in-flight task, and the loop's re-check and `refreshTask = nil` happen with no suspension between them, so no refresh is lost. A partial merge keeps siblings from `lastSnapshots` or the store. `QuotaSeriesStore.append` dedupes the carried-over readings.
- AC3: the deadline is computed from `lastFileRefresh`, not reset by each new event, so a continuous writer cannot starve it. The last event of a burst is scheduled. Becoming visible flushes the watcher batch and the dirty set. The periodic 300 s `refreshAll()` stays full.
- AC4: the Cline cache key (size, mtime ns, ctime ns, inode on the resolved target) catches same-size rewrites, truncation and atomic replacement. A write during the read is not cached. The Antigravity state skip includes `-wal` and `-journal`.
- Harness: positive home check, disposable bundle id, terminate+wait in `finally` on SIGINT/SIGTERM, copied app only. No other leftovers found in `~/Library/{Caches,HTTPStorages,Saved Application State,Application Support,WebKit,Containers}`.
- `import AppKit` in `SyncEngine`: the CLI target does not compile Core sources, so this has no CLI impact.
