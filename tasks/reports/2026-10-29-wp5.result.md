## Behavior and constraints

- Regular `.jsonl` and `.jsonl.zst` files are discovered; directories and symbolic links are excluded. A plain file wins over its compressed counterpart.
- Both formats use the same 16 MiB JSONL framer, including oversized-record recovery, CRLF and complete unterminated final records.
- A process-wide actor caches successful and failed compressed attempts by fresh size, mtime, inode and device. Concurrent parsers, calendar changes and `/var` versus `/private/var` aliases cannot decompress the same fingerprint twice. Metadata changes or replacement permit a new attempt.
- The cache retains compact dated usage/model/tier records, without conversation text or complete decoded logs. Calendar aggregation can be rebuilt without decoding. A calendar epoch prevents stale reentrant work from restoring old date buckets.
- Complete decoding, checksums and a post-read fingerprint check must succeed before a file contributes usage. Failure discards all provisional records, gives one info warning for that source per snapshot, and leaves other files visible. Failure is cached too.
- Pure Swift handles raw/RLE/compressed blocks, Huffman/FSE/sequences, repeated tables/offsets, multiple frames and verified XXH64 checksums. Dictionaries fail cleanly. Window ≤128 MiB and decoded output ≤256 MiB per file; bounds are checked before reads and copies.
- Existing file watching covers the Codex sessions directory without filtering extensions. The app does not invoke zstd; it is only an independent test reference.
