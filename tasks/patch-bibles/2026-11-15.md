## 0. Why these (read from the code and the web, 2026-11-15)

- Already shipped, so NOT rebuilt: the pace verdict and forecast (`Core/Utilization/QuotaPace.swift`), the
  route-here chip (`RouteTargetPolicy`, `MaxxerMath.routeTarget`), plan presets, per-provider alert thresholds,
  lifetime totals, MCP protocol negotiation. GitHub issues #36, #37, #41, #51, #60 are stale.
- Rivals (research 2026-11-15): about ten menu-bar trackers now show pace. One (MeterBar) ranks plans by headroom
  with a `route` CLI. None lets the coding agent itself ask "which plan next" over MCP, none pairs routing with
  dollar value, and none publishes a measured footprint with its method. CodexBar users report 900 MB and 80-134% CPU.
- Tokei's own cost: 0.12.0 measured idle CPU 2.17% with the window closed. Every file event in any agent's
  session folder triggers a refresh of every provider (`FileWatcher` 2 s debounce → `SyncEngine.refreshAll`).
  There is no repeatable performance check.

So 0.13.0 is: **routing an agent can ask for**, and **a footprint that is measured and budgeted**.

## 3. Shared rules for every lane

- Work ONLY in your worktree. Never touch `~/src/tokei-macos` (main checkout) or another lane's worktree. The one
  exception is your result file at the absolute path in your brief.
- Build and test with your own DerivedData: `-derivedDataPath ~/Library/Developer/TokeiWork/dd-<slug>`. Run
  `xcodegen generate` in `AIUsageDashboard/` first. Run targeted tests (`-only-testing:`), never the whole suite;
  the orchestrator runs the full suite once at integration.
- Bugs and behaviour changes: a test that fails on the old code first. No test weakened or deleted.
- Commit in small slices; the pre-commit gate runs; never `--no-verify`. No new dependencies. No new network
  calls. Never read or print credentials, keychain items, `.env` files or auth files.
- The repo is public. Proof screenshots, recordings and logs with real usage never go in git; put them under
  `~/Library/Developer/TokeiWork/proof/<lane>/` and list the paths in the result file.
- No merge, no push, no PR, no deploy. The orchestrator does those.
- Copy: sentence case, no eyebrow labels or numbered kickers, no em dashes in user-facing text. Nothing ever
  points a user or an agent at paid credits or overage (0.12.0 rule).
- Result file `tasks/herd/2026-11-15/<lane>.result.md` in the MAIN checkout (absolute path in the brief): line 1
  `STATUS: READY` or `STATUS: BLOCKED`; then each AC with its check and the command output lines that prove it;
  commits; contract additions; known gaps. Then send the one-line report the brief names.

## 5. Work packages

### WP-A · Speed: targeted refresh and a perf harness — Codex Sol
- **Scope in:** `AIUsageDashboard/AIUsageDashboardApp/Core/{Sync,Utilities,Parsing,Providers,Network}/**`,
  their tests, `AIUsageDashboard/scripts/perf-bench.sh` + `perf-budget.json`, `docs/FEATURES.md` (one entry).
- **Scope out:** `UI/**`, `TokeiCLI/**`, `Core/Agent/**`, `Core/Utilization/**`, `Core/Game/**`, `App/**`
  (except a minimal hook the harness needs, named in the result).
- **Acceptance criteria (each with its check):**
  1. **Harness.** `scripts/perf-bench.sh <path to Tokei.app>` runs a given build against a synthetic home (temp
     dirs through the existing `CLAUDE_CONFIG_DIR`, `CODEX_HOME` and similar overrides; never the real logs),
     with a writer appending to one synthetic session log every second, and reports as one JSON line plus a
     table: average CPU % over 120 s with no window open, physical footprint MB, cold launch to first window ms,
     and how many provider refreshes ran per provider. Exit non-zero when over `perf-budget.json`. Check: run it
     on a Release build of `dev` (baseline) and of the branch; both outputs in the result.
  2. **Targeted refresh.** A file event under one provider's folder refreshes that provider only. Check: a test
     with counting fake providers; it fails on the old code.
  3. **Calm when nobody is looking.** With no Tokei window or popover visible, a provider being written to
     continuously refreshes at most once per 15 s; opening the popover or window catches up at once (within the
     existing 2 s debounce). The menu bar label may therefore lag by up to 15 s. Check: a test with an injected clock.
  4. **No whole-file rereads.** Confirm with a counting test whether Cline (`ClineMessagesParser`) rereads
     unchanged files on every refresh; if it does, cache by size and modification time. Same question for the
     SQLite sidecar copies (`SQLiteSidecarCopy`, including the `-wal` file): skip the copy when unchanged.
  5. **Subprocess spawns** (`ClaudeUsageClient`, `CodexRateLimitClient`, `AntigravityQuotaClient`) are never
     started by a file-event refresh more often than their own network cadence. Check: read first; test if a change is needed.
  6. **Numbers unchanged.** Existing parser, sync and analytics tests pass untouched; a new test shows a targeted
     refresh and a full refresh produce equal snapshots for the same fixture.
  7. **Measured win.** On the harness, average CPU with an agent writing drops by at least half against the
     baseline, and footprint does not grow. If it does not reach half, report the numbers and what dominates
     (a sample or `xctrace` summary); do not tune the harness to pass.
- **Risks:** stale numbers (AC 3 and 6 guard it); FSEvents path → provider mapping wrong for shared parents.
- **Rollback:** `git revert -m 1 <merge sha>`.

### WP-B · Route: a ranked plan recommendation agents can ask for — Codex Sol
- **Scope in:** `Core/Utilization/Route*.swift` (new `RoutePlan`), `Core/Agent/**`, `TokeiCLI/**`, their tests,
  the CLI version build step (`project.yml`, `.claude/gates/cli-version-sync.sh`), `docs/FEATURES.md` (one entry).
- **Scope out:** `UI/**` (WP-C wires the UI), `Core/{Sync,Parsing,Providers,Network}/**` (WP-A).
- **Acceptance criteria:**
  1. **One rule, one place.** `RoutePlan.make(snapshots:now:)` returns the ranked list of plan-backed agents
     with, per row: provider, account label when there are several, the deciding window, percent left, time to
     reset, pace state, and one plain reason sentence. Order: (a) capacity that expires soon and would go unused
     (`ExpiringHeadroomFinder`), soonest first; (b) then most room relative to pace; exhausted or nearly exhausted
     plans last and marked "avoid"; stale or untrusted readings excluded and listed as "unknown". Pay-per-token
     agents are never recommended. The existing `RouteTargetPolicy` answer equals the first row whenever it
     gives one, so the chip and the agents can never disagree. Check: table-driven tests, including ties, one
     plan, no plans, all exhausted, stale data.
  2. **Agent snapshot** gains an additive `route` block (ranked rows, generated-at). Existing keys untouched.
     Check: a snapshot test, and the existing snapshot tests pass unchanged.
  3. **MCP tool `get_route`**: "Which plan should the next task go to." Returns the ranked rows and one advice
     line, short plain text only (same sanitising as window labels), with an optional `for` argument to ask
     "is this agent a good place right now". The server instructions tell an agent when to call it, in under
     400 characters. Existing tools unchanged. Check: protocol tests for all three protocol revisions.
  4. **CLI `tokei route [--json] [--for <agent>]`**: one screen; exit 0 with a recommendation, a distinct
     non-zero code when every plan is exhausted, another when the data is missing or stale. Follow `tokei
     guard`'s existing conventions; document the codes in `tokei help`. Check: tests on formatting and exit codes.
  5. **CLI version** comes from `MARKETING_VERSION` at build time (issue #61); the sync gate still guards it.
  6. **Real proof.** Build the CLI and run against this Mac's live agent snapshot (read-only): `tokei route`,
     `tokei route --json` (valid JSON), and an MCP `initialize` + `tools/list` + `tools/call get_route`. Paste
     the output with account labels and email-like strings redacted.
- **Risks:** a recommendation that contradicts the UI chip (AC 1); leaking account names to agents (AC 3).
- **Rollback:** `git revert -m 1 <merge sha>`.
