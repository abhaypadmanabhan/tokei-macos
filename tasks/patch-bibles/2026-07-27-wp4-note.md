- **Risks / watch-outs:**
  1. **One deviation from the letter of the scope, flagged for review.** The package said
     "`project.yml`: `AIUsageDashboardCoreTests.sources` list ONLY". Getting the CLI files
     to compile in the test bundle also needs one build setting on that target:
     `SWIFT_ACTIVE_COMPILATION_CONDITIONS: $(inherited) TOKEI_CLI_TESTS`. The CLI files must
     `import AIUsageDashboardCore` in the test bundle and must NOT in the `tokei` tool
     target (which compiles `AgentSnapshot.swift` directly and must stay standalone), and
     a Swift import is file-scoped, so a shim file cannot supply it. Per-file
     `compilerFlags: -DTOKEI_CLI_TESTS` was tried first and **does not work** — xcodegen
     emits `COMPILER_FLAGS`, but Xcode ignores per-file flags for Swift because a module
     compiles in one invocation (build failed with `cannot find type 'AgentSnapshot'`).
     `#if canImport` was rejected on purpose: the framework sits on the tool target's
     implicit search path whenever it happens to have been built, so the standalone tool
     would link Core nondeterministically. The setting lives in
     `AIUsageDashboardCoreTests.settings.base`, which is **disjoint from the Core/App/tokei
     signing blocks WP-1 owns** — no textual overlap — but it is a `settings:` line, so
     call it out at merge.
  2. **Fixtures live in `Tests/Fixtures/AgentSnapshotFixtures.swift`, not `Fixtures.swift`.**
     Still Swift string literals, no resource files, matching the four sibling
     `*Fixtures.swift` files already in that directory. Appending them to `Fixtures.swift`
     pushed it from 379 to 483 lines and introduced a **new** swiftlint `file_length`
