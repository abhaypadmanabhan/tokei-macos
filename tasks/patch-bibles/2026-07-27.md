- **Worktree:** `../tokei-worktrees/2026-07-27-release-signing` (branch `patch/2026-07-27/release-signing`)
- **Scope (in):** `AIUsageDashboard/project.yml` (**`settings:` / `configs:` signing blocks
  ONLY**), `AIUsageDashboard/scripts/build-app.sh`, other `AIUsageDashboard/scripts/*`
  release helpers, `.claude/gates/build.sh` if the gate needs to assert launchability,
  release docs under `AIUsageDashboard/docs/`.
- **Scope (out):** every `.swift` file. The `sources:` lists in `project.yml` (WP-4 owns
  `AIUsageDashboardCoreTests.sources`). Notarization/appcast publishing — this package
  makes the app *launch*, it does not cut a release.
- **Reproduce first (non-negotiable):** build with the current tree and confirm the failure
  before changing anything.
  ```bash
  cd AIUsageDashboard && bash scripts/build-app.sh
  open -W dist/Tokei.app || true          # expect the dyld Team ID failure
  codesign -dvv dist/Tokei.app 2>&1 | grep -iE 'team|authority|flags'
  codesign -dvv dist/Tokei.app/Contents/Frameworks/AIUsageDashboardCore.framework 2>&1 | grep -iE 'team|authority|flags'
  ```
  Expected dyld error:
  `Library not loaded: @rpath/AIUsageDashboardCore.framework/… Reason: … mapping process and mapped file (non-platform) have different Team IDs`
- **Leading hypothesis (verify, do not assume):** `build-app.sh:9` defaults
  `CONFIG="${TOKEI_CONFIG:-Release}"`, so an ordinary dev build uses the **Release**
  configuration. In that configuration `project.yml:83` sets `ENABLE_HARDENED_RUNTIME: YES`
  on `AIUsageDashboardApp`, while `AIUsageDashboardCore` (`project.yml:38-42`) does **not**
  — it inherits the base `NO`. Without `TOKEI_RELEASE=1`, `build-app.sh` forces
  `CODE_SIGN_IDENTITY="-"` (ad-hoc) on the command line and **skips the whole inside-out
  re-sign block**. Result: a hardened-runtime, ad-hoc-signed app. Hardened runtime enables
  **library validation**, which demands the loaded framework carry the same Team ID — an
  ad-hoc signature carries none. That is exactly the reported dyld error.
  A second, non-exclusive contributor to rule in or out: `-derivedDataPath
  "$ROOT/build/DerivedData"` is persistent, so a framework left over from an earlier
  `TOKEI_RELEASE=1` build can survive into a later ad-hoc build.
- **Acceptance criteria:**
  - [ ] The failure is reproduced and the *actual* root cause is stated with `codesign`
        evidence, before any fix lands. If the hypothesis above is wrong, say so and follow
        the evidence.
  - [ ] `bash scripts/build-app.sh` (no env) → `dist/Tokei.app` **launches** and stays up.
        Prove it: `open dist/Tokei.app`, then confirm the process is alive
        (`pgrep -f 'dist/Tokei.app/Contents/MacOS/Tokei'`) and no dyld error appears in
        `log show --last 2m --predicate 'process == "Tokei"'`. Kill it afterward.
  - [ ] `TOKEI_RELEASE=1 bash scripts/build-app.sh` → `dist/Tokei.app` **launches**, and
        `codesign --verify --strict --deep dist/Tokei.app` exits 0.
  - [ ] App, `AIUsageDashboardCore.framework`, `Sparkle.framework` and `Contents/Helpers/tokei`
        all report a **consistent** Team ID and hardened-runtime flag under `codesign -dvv`.
  - [ ] `spctl -a -vvv -t exec dist/Tokei.app` on the `TOKEI_RELEASE=1` build is reported
        (accepted, or the exact rejection reason recorded — unnotarized rejection is expected
        and fine; a *signing* rejection is not).
  - [ ] Both paths remain idempotent and re-runnable from a clean tree.
- **Test requirements:**
  - [ ] `./.claude/gates/test.sh` stays green (no Swift changed, so this is a regression guard).
  - [ ] Add a launch assertion to the build path — either in `scripts/build-app.sh` (fail the
        script if the freshly built app cannot load its own framework) or in
        `.claude/gates/build.sh`. A build that produces an unlaunchable app must not exit 0

  - [ ] Record the before/after `codesign -dvv` output in the §8 completion note.

### WP-2 · Core client hygiene (handoff P1 + P2 + P5) — Claude Code (Sonnet)

- **Worktree:** `../tokei-worktrees/2026-07-27-core-client-hygiene` (branch `patch/2026-07-27/core-client-hygiene`)
- **Scope (in):** `Core/Network/CursorUsageClient.swift`, `Core/Network/AntigravityQuotaClient.swift`,
  a new shared helper under `Core/Network/` (see below), `Core/Providers/ClaudeCodeProvider.swift`
  (**`discoverLogSources()` only**), `Core/Providers/LocalLogProvider.swift` (protocol/doc only if
  the contract genuinely needs to express partial failure), tests under `Tests/ProviderTests/`.
- **Scope (out):** `Core/Agent/**`, `Core/Maxxer/**`, all of `UI/**`, `project.yml`,
  `Core/Network/CooldownStore.swift` semantics, and any behaviour change to
  `Core/Network/ClaudeUsageClient.swift` (read it as the reference implementation; see risk).
- **The three defects:**
  1. **P1 — retry storm.** `CursorUsageClient.swift:129`:
     ```swift
     await sleep(min(retryAfter ?? cooldownStore.defaultCooldownInterval, Self.maxRetrySleepInterval))
     ```
     Sleeps its own 30s ceiling and then retries against an arbitrarily long `Retry-After`.
     Apply the same early-exit already landed in the Claude client:
     `if let retryAfter, retryAfter > maxRetrySleepInterval { throw .rateLimited(...) }`.
     Add the missing 429/401/non-2xx logging — this path currently logs nothing.
     **Note:** Cursor serves no stale quota cache, so it has **no** P3-style decay and no
     stale-routing exposure. This is retry behaviour only — do not add cache decay here.
  2. **P2 — unstructured staleness.** `AntigravityQuotaClient.swift:182` hand-appends
     `"antigravity-local-rpc (stale)"` and sets no `observedAt`. Adopt the structural
     `observedAt` that `f725bac` added to `QuotaWindow`. It already downgrades to
     `confidence: .estimated`, so WP-3/`AgentRecommendationEngine`'s gate already blocks
     routing to it — **this is not a live routing bug**, it is convention debt.
  3. **P5 — swallowed errors.** `ClaudeCodeProvider.discoverLogSources()` unions across
     accounts with `try?` per account, so a genuinely broken directory no longer throws.
     `fetchSnapshot` still warns correctly via the private per-account path. Decide, and
     document in the code, whether the public `LocalLogProvider` contract should surface
     partial failure — then make the code match the decision. "All accounts failed" must not
     be indistinguishable from "no accounts configured".
- **The shared helper (the point of bundling these):** nothing today stops the *next* client
  from forgetting `observedAt` or re-implementing the retry ceiling. Extract one small,
  tested helper in `Core/Network/` that owns (a) the `Retry-After` early-exit decision and
  (b) stamping `observedAt`, and have Cursor and Antigravity both adopt it. Keep it boring —
  a couple of free functions or a small struct, not a framework.
- **Acceptance criteria:**
  - [ ] A `Retry-After` longer than `maxRetrySleepInterval` causes `CursorUsageClient` to
        throw `.rateLimited` **immediately** — exactly one request, no sleep-and-retry.
  - [ ] `CursorUsageClient` logs on 429, 401 and any non-2xx, with the status code.
  - [ ] `AntigravityQuotaClient` sets a real `observedAt` and no longer concatenates
        `" (stale)"` into its source string.
  - [ ] `discoverLogSources()` no longer silently reports success when every account failed;
        the chosen contract is documented in a doc comment on the declaration.
  - [ ] Both clients route their retry/staleness decision through the one shared helper.
- **Test requirements:**
  - [ ] Extend `Tests/ProviderTests/CursorUsageClientTests.swift`: long `Retry-After` → one
        request + throw; short `Retry-After` → honoured; 429/401 surface correctly.
  - [ ] Extend `Tests/ProviderTests/AntigravityQuotaClientTests.swift`: `observedAt` is set;
        source string is clean.
  - [ ] Add a test for `discoverLogSources()` all-accounts-fail vs no-accounts.
  - [ ] Direct unit tests for the shared helper.
  - [ ] Every existing test stays green — **especially** `Tests/AgentTests/*`.
- **Known risks:**
  - Refactoring `ClaudeUsageClient.swift` onto the new helper could regress the fix that
    just landed in `f725bac` → **mitigation:** adopting the helper in `ClaudeUsageClient` is
    **optional and last**. Only do it if every test stays green and the diff is genuinely
    smaller. If there is any churn, leave `ClaudeUsageClient` alone and say so in §8.
  - Adding cache decay to Cursor by pattern-matching the Claude fix would be wrong →
    **mitigation:** explicitly out of scope above.
- **Rollback:** revert the merge commit; branch retained.

    become the agent rule.

  `"route to Claude Code (tightest window 7%)"` without saying which account owns that 7%.
  The data is already in `accounts[]` — `AgentAccount.id` is the path to set
  `CLAUDE_CONFIG_DIR` to. Put the account into the human-readable line so an agent reading
  the reason knows what to export.
