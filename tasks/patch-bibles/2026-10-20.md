## 1. Frozen contracts (already on dev — do not change their shape)

- `QuotaWindow.windowDuration: TimeInterval?` — full window length when known. Persisted.
- `ProviderSnapshot.dailyModelUsage: [Date: [String: TokenUsage]]?` — tokens per start-of-day
  per raw model slug. Persisted. Every `ProviderSnapshot(` you build must carry it through.
- `MaxxerProviderValue.models: [MaxxerModelValue]` — MTD value per model, largest first;
  `MaxxerModelValue{model, totalTokens, apiEquivalentUSD: Double?}` (nil = no public rate).

- **Worktree:** `../tokei-worktrees/2026-10-20-value-by-model` (branch `patch/2026-10-20/value-by-model`)
- **Scope (in):** `Core/Parsing/ClaudeJSONLParser*.swift`, `Core/Parsing/ClaudeUsageRecord.swift`,
  `Core/Parsing/CodexJSONLParser.swift`, `Core/Providers/ClaudeCodeProvider.swift`,

  `Core/Maxxer/MaxxerValueEngine.swift`, tests under `Tests/{ParserTests,PricingTests,MaxxerTests,ProviderTests}`.
- **Scope (out):** UI, quota code, `CodexProvider` quota path (WP-2 owns it), the frozen contracts.
- **Acceptance criteria (each with its check):**
  1. Claude records capture `message.model`; records whose model is `<synthetic>` contribute no
     tokens (T3 rule). Parser fills `dailyModelUsage` per account and the provider merges accounts.
     Check: parser unit test with a fixture holding two models + one `<synthetic>` row.
  2. Codex records carry the model from the most recent `turn_context` in the same file (T3 rule);
     a `token_count` before any `turn_context` goes under model `"unknown"`. Parser fills
     `dailyModelUsage`. The parse cache must persist the carried model across incremental appends.
     Check: unit test with model switch mid-file + an append that resumes after the switch.
  3. Rates resolve from the LiteLLM table (`PricingService`) with `PricingSeed` overrides; the seed
     gains current rows so an offline first launch prices correctly: `claude-opus-5-5` (4/0.2/5/20 per M:
     input/cached/cacheWrite/output), `claude-opus-5` (5/0.5/6.25/25), `claude-fable-5-1` (10/0.25/12.5/50),
     `claude-sonnet-5-5` (2/0.1/2.5/10), `claude-haiku-5-5` and `gpt-6.1-sol`, `gpt-6-astra`, `gpt-6-sol`
     from the LiteLLM table on disk. Normalize a trailing `[1m]` and an 8-digit date suffix before lookup.
     An exact slug wins over a family prefix (`claude-sonnet-5` must not price `claude-sonnet-5-5`).
     Unknown models stay unpriced (no guessed rate). Check: `PricingTests` for each rule.
  4. `MaxxerValueEngine` prices **month-to-date** per model from `dailyModelUsage` when present (no
     MTD scaling hack for those providers), fills `models` (largest $ first, unpriced rows last),
     sets `hasUnpricedTokens` when any model is unpriced, keeps the reference-model fallback for
     providers without `dailyModelUsage` (Cursor). `CodexProvider.costUsage` prices per model too
     (no longer lifetime × latest model). Check: `MaxxerTests` with a two-model + one-unpriced fixture.
  5. Real-corpus proof: under `TOKEI_REAL_LOGS=1`, a smoke test prints `REAL-LOGS value-by-model`
     MTD $ per model for Claude and Codex. The orchestrator diffs it against the Python baseline;
     must agree within 0.5 % per provider. (Do not run the real-logs suite more than once.)
  6. No CPU/RAM regression: per-model maps are per day (≤ ~31 days × few models), not per record.

### WP-2 · Live Codex quota + 5-minute quota refresh (T3 probe) — Codex `gpt-6.1-sol`
- **Worktree:** `../tokei-worktrees/2026-10-20-codex-live-quota` (branch `patch/2026-10-20/codex-live-quota`)
- **Scope (in):** new `Core/Network/CodexRateLimitClient.swift`, `Core/Providers/CodexProvider.swift`
  (quota path only), `Core/Providers/CodexAccountDiscoverer.swift` if needed, `Core/Sync/SyncEngine.swift`,
  `UI/Components/ProviderMetadata.swift` (toggle key mapping only), tests.
- **Scope (out):** parsers, pricing, Maxxer, all other UI, the frozen contracts.
- **Protocol (verified live 2026-10-20, codex-cli 0.163.0):** spawn `codex app-server` (stdio,
  newline-delimited JSON-RPC 2.0). Send `{"id":1,"method":"initialize","params":{"clientInfo":
  {"name":"tokei","title":"Tokei","version":<app version>}}}`, then notification `{"method":"initialized"}`,
  then `{"id":2,"method":"account/rateLimits/read","params":null}`. Result: `rateLimits{limitId,
  planType, primary/secondary{usedPercent, windowDurationMins, resetsAt epoch-s}, credits{hasCredits,
  unlimited, balance}}`, `rateLimitsByLimitId{…}`, `rateLimitResetCredits{availableCount, credits[]}`.
  Terminate the child after the answer. T3 reference: `apps/server/src/provider/codexUsageLimits.ts`.
- **Acceptance criteria:**
  1. Client returns `QuotaWindow`s, `confidence .providerReported`, `observedAt = now`,
     `windowDuration = windowDurationMins × 60`, type from duration (≤ 6 h → session, ≈ 7 d → weekly,
     ≥ 28 d → monthly) because primary/secondary are positions, not durations (T3 rule). Only
     `limitId == "codex"` counts. Credits keep the existing credits-window convention (balance →
     `remaining`, `used = nil`). Reset credits surface as a window or label only if it fits the
     existing model without a schema change — otherwise leave them out and say so.
     Check: unit tests on captured response fixtures (account id removed).
  2. Hard 5 s timeout, child killed on timeout, bounded stdout read (reuse the MCP bounded POSIX
     reader pattern from 0.9.0 if it fits). No credentials read by Tokei. Binary resolution: the
     `codex` on known install paths (`/opt/homebrew/bin`, `/usr/local/bin`, `~/.local/bin`,
     `~/.npm-global/bin`, `~/.bun/bin`, newest `~/.local/share/fnm/node-versions/*/installation/bin`,
     `~/.nvm/versions/node/*/bin`) — never a login shell. Missing binary → log fallback, no warning spam.
     Check: unit tests with an injected process runner (success, timeout, garbage output, no binary).
  3. Live reading wins over the log reading for the same account when fresher; a failed probe keeps
     the last good live reading until it is older than the log reading (T3 `probeFailed` keeps bars,
     never blanks them). Account match: Codex `auth.json` account vs the probe's `accountId`
     (hash both, never store or log the raw id).
  4. Setting `codexLiveQuotaEnabled`, **default ON when unset**; mapped in `ProviderMetadata` so
     the existing Settings network-toggle row appears; the row must show ON on a fresh install.
  5. `SyncEngine` refreshes every 5 min while running (T3 default), coalesced with file-event
     refreshes (no overlapping `refreshAll`), cancelled in `stopAutoSync`.
     Check: unit test with an injected clock/sleeper.
  6. Live proof: debug build running → `~/Library/Application Support/AIUsageDashboard/agent-snapshot.json`
     shows Codex windows with `source` naming the live probe, `observedAt` < 6 min old, and
     account `quota.status == eligible` (today it is `unknown/untrusted_reading`).
     Idle CPU over 10 min with the window closed stays ≤ 1 % average (`ps -o %cpu` sampling;
     record before/after numbers in the result file).

## 4. Rules for every agent
- First line of your work: `cd <your worktree>`; work ONLY in that directory. Never touch `dev`,
  `main`, other worktrees, or push. Commit on your branch only; never `--no-verify`.
- `cd AIUsageDashboard && xcodegen generate` before building (the `.xcodeproj` is gitignored).
- TypeScript-style strictness applies in spirit: no force unwraps on parsed data, no `try!`.
- A new stored property on a persisted type goes through `Core/Storage/ModelCodableExtensions.swift`.
- Never read or print credentials (`auth.json` tokens, Keychain items, `oauth_creds.json`).
- Do not run the `TOKEI_REAL_LOGS=1` suite more than once (it costs minutes of CPU).
