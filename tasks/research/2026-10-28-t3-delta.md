## 4. Antigravity port spec (precise enough to implement in Swift)

### 4.1 Where the files are

Verified on this Mac (counts are files):

| Root | `conversations/` contents |
|---|---|
| `~/.gemini/antigravity` | 20 `*.db` (+ `-wal`, `-shm`), 101 `*.pb` |
| `~/.gemini/antigravity-cli` | 11 `*.db` (+ `-wal`, `-shm`) |
| `~/.gemini/antigravity-ide` | 100 `*.pb`, no `.db` |
| `~/.gemini/antigravity-backup`, `~/.config/antigravity` | absent here |

- T3 default roots: `~/.gemini/{antigravity,antigravity-cli,antigravity-ide,antigravity-backup}` and `~/.config/antigravity` (`AntigravityUsage.ts:45-50`). Override: env `ANTIGRAVITY_DATA_DIR`, comma-separated, `~/` expanded (`:41-44, 52`).
- Per root: `realpath` it (fall back to the plain path). Use `<root>/conversations` if that exists, else the root itself. Dedupe the resulting dirs after `realpath` (`:85-95`).
- Swift glob: `~/.gemini/antigravity*/conversations/**/*.db` plus `~/.config/antigravity/conversations/**/*.db`.
- Walk recursively, names sorted by locale compare. Symlinks are skipped (neither file nor directory). A file counts only if the name ends `.db`, so `-wal`, `-shm` and `.pb` are ignored (`antigravityUsageReader.ts:433-475`).
- `.pb` files: 7.997 bits/byte entropy on a 64 KB sample, no readable header (encrypted or compressed). T3 ignores them. Unverified: whether they can be decoded. History before the `.db` format is therefore not recoverable.
- Session id = file name without `.db` (a UUID). Fallback timestamp for a DB = its file mtime in ms.

### 4.2 SQLite layout (verified)

Tables in all 31 DBs: `trajectory_meta`, `steps`, `gen_metadata`, `executor_metadata`, `parent_references`, `trajectory_metadata_blob`, `battle_mode_infos`. Only three are read:

```
steps(idx INTEGER PK, step_type, status, has_subtrajectory, metadata BLOB, ..., step_payload BLOB, step_format)
gen_metadata(idx INTEGER PK, data BLOB, size INTEGER)
trajectory_metadata_blob(id TEXT DEFAULT "main", data BLOB)
```

A DB with neither `gen_metadata` nor `steps` is a decode error. Missing `trajectory_metadata_blob` is fine.

Queries (T3 `:195-259`):
- `PRAGMA busy_timeout = 100`, then everything inside one read transaction.
- Generations: `SELECT rowid AS row_id, idx, data FROM gen_metadata WHERE rowid > ? ORDER BY rowid LIMIT 1`, looped, one row per page. Blobs reach 847 KB here; never `SELECT *`.
- Steps: `SELECT rowid AS row_id, idx, metadata AS data FROM steps WHERE rowid > ? ORDER BY rowid LIMIT 64`, looped. Skip rows with NULL `metadata`. Never read `step_payload`. Max `metadata` here: 58 KB.
- `idx` must be an integer, else decode error. Sort both lists by `idx` after reading.
- Trajectory timestamp: `SELECT data FROM trajectory_metadata_blob`; first non-null of `Timestamp(field 2)` wins.

### 4.3 Protobuf reader (what to build; the existing `MiniProtobufReader` guesses nested messages and is the wrong tool)

Build a schema-directed reader: parse a message into `[Int: [Value]]`, then pull fields by number.

- Tag = varint; field number = tag >> 3, wire = tag & 7. Field 0 is an error.
- Wire 0: varint, up to 10 bytes; on the 10th byte a value above 1 is an error (so 64-bit max). Values above 2^53 are kept but count as "not a number" (read as 0).
- Wire 2: length-delimited; length greater than the remaining bytes is a "truncated" error.
- Wire 1 and 5: skip 8 and 4 bytes, store nothing.
- Wire 3, 4, 6, 7: error. One such field makes the whole DB fail (it is reported as partial, other DBs still count).
- Repeated fields keep order. Every accessor reads the first entry only. Missing or wrong type gives 0 or nil.
- Text = strict UTF-8 (invalid bytes are an error), then trimmed.
- Unknown field numbers are parsed and ignored. A test in T3 (`antigravityUsageReader.test.ts:395-414`) puts a max-width 10-byte varint in an unused field and expects no error.
- `Timestamp` message: field 1 seconds, field 2 nanos. `ms = seconds*1000 + nanos/1_000_000`; seconds <= 0 gives nil (`:76-79`).

### 4.6 Dedupe (T3 `:297-300, 349-410, 480-486`)

Each usage message becomes a candidate. Order of creation: all steps by `idx`, then all generations by `idx`, files in sorted path order; retry usages follow their row's primary.

- `keys` = for `k` in `[11, 12, 7]`: if `text(U,k)` is non-empty, `"antigravity:<k>:<text>"`.
- `dedupeKey` = first key, else `"antigravity:<sessionId>:<source>:<index>:<usageIndex>"` (`index` is the position in that source's `idx`-sorted list). Candidates without keys never merge.
- Union-find over all candidates from all files in one scan: two candidates join when they share any key.
- Merged record: fields of the lowest-numbered member (owner); model replaced only if the owner's is `antigravity-unknown`; each token bucket is the MAX over members (not the sum); timestamp = best by quality (2 = row's own timestamp, 1 = trajectory timestamp, 0 = file mtime), ties to the earlier time. Attributed to the owner's file.
- Emit group roots with `timestampMs >= windowStart`.

Why it matters (oracle on this Mac): 4700 raw candidates collapse to 1587 records; a naive sum is 2.9x the deduped total (35.7M vs 12.19M uncached, 349.1M vs 118.75M cached, 2.96M vs 1.01M output).

### 4.7 Concurrent writes, caching, errors

- Open read-only, `busy_timeout` 100 ms, one read transaction. Tokei's existing `SQLiteSidecarCopy` (backup API into a private temp dir) is an equivalent and already shared by the Cursor, opencode and Antigravity-state parsers. It copies whole files (46 MB for 31 DBs here), so gate it behind the fingerprint.
- Fingerprint per canonical DB path: `"<size>:<mtimeMs>:<ctimeMs>"` of the `.db`, `/`, the same triple for `<db>-wal` or `-` when there is no WAL (`:416-423`). WAL holds new rows and is the file that changes first; ctime catches restored mtimes. Equal fingerprint returns the cached candidates. Cache entries not visited in a scan are dropped. T3 test: a WAL-only change with equal size and mtime on the main file triggers a re-read (`antigravityUsageReader.test.ts:342-370`).
- A DB that is not SQLite, fails a query, or has a protobuf error is added to `errors`; the scan reports `partial` with "Some Antigravity history could not be read." and still returns every other DB (`AntigravityUsage.ts:105-113`). A directory that does not exist is not an error; any other read failure is.
- Unknown protobuf fields and unknown model ids never fail a read. Only the wire-type, truncation, varint, UTF-8 and missing-`R.1` cases do.

## 5. Codex service-tier (priority/fast/flex) pricing notes

Where the tier is read (verified on Codex CLI 0.165.0; 112 of about 113 rollouts carry the event):
- Event: `{"type":"event_msg","timestamp":...,"payload":{"type":"thread_settings_applied","thread_id":...,"thread_settings":{"service_tier":"default","model":...,"reasoning_effort":...,...}}}`.
- It appears after the first `turn_context` and before the first `token_count` (line indexes 2, 8, 22 in a sample). `turn_context` itself has no tier in this version.
- Observed values here: only `"default"` (152 events). T3 maps `"priority"` and `"fast"` to fast, `"ultrafast"` to ultrafast, anything else (missing, `""`, `default`, `standard`, `flex`) to standard (`codexUsage.ts:298-303`, tests `codexUsage.test.ts:110-130, 415-440`).
- State is carried forward per rollout: tier from the latest `thread_settings_applied`, model from the latest `turn_context`; each `token_count` record stamps both (`:64-69, 167-174, 280-295`).
- If a rollout has no `thread_settings_applied` yet and `session_meta.model_provider == "openai"`, T3 looks the tier up in its own orchestration DB (`CodexUsageHistory.ts:54-115`, `codexUsage.ts:342-368`). That is T3-internal; Tokei should treat it as standard.

Rate source (verified against the live LiteLLM JSON, 4427 models):
- Codex: per-token keys with a suffix. `input_cost_per_token_priority`, `output_cost_per_token_priority`, `cache_read_input_token_cost_priority` (340 models). `*_ultrafast` on 8 models. `*_flex` on 252 models; T3 ignores flex and batches (`usagePricing.ts:17`).
- Observed multipliers: priority = 2x on gpt-5, gpt-5.1, gpt-5.3-codex, gpt-5.4, gpt-6-astra, gpt-6.1-sol, gpt-6-sol; 2.5x on gpt-5.5. Ultrafast = 6x on gpt-6-astra ($60/M in, $300/M out) and gpt-6.1-sol ($12 in, $60 out).
- Claude fast mode: `provider_specific_entry.fast` multiplier (2 on claude-opus-5-5, claude-opus-5, claude-opus-4-8), applied to all four rate fields (`usagePricing.ts:76-90, 105-111`). Claude transcript marker: `message.usage.speed == "fast"` (`claudeUsage.ts:74`); 141,433 of 141,433 records here are `"standard"`.
- Fallbacks: a tier field missing for one rate (for example no `cache_read_*_priority`) is scaled from the standard cache-to-input ratio times the tier input rate (`usagePricing.ts:52-74`). A model with no tier rates prices at standard (`ratesAt`, `:158-160`). Overrides never get a tier. `reportedCostUsd` wins over list price and the premium is scaled to it (`:237-276`).
- Premium = tier list cost minus standard list cost of the same tokens. Cache savings use the tier's own input minus cache-read rate (`:278-288`).

Tokei changes: add `speed` to the per-record state in `CodexJSONLParser`, split per-model daily tokens by tier, add `priority/ultrafast` rates to `PricingTable` rows, show "Premium $X". Unverified: what a Fast-mode Codex session writes for `service_tier` on the current CLI (no such session on this Mac); T3 accepts `priority`, `fast`, `ultrafast`.

## 6. How T3 presents usage (apps/web, apps/mobile)

Layout:
- Usage page has three metric tabs, Cost, Tokens, Limits (keys `C`, `T`, `L`; `docs/user/usage.md` "Keyboard shortcuts"). Headline figure `text-4xl`, under it "N sessions · API estimate" and an info popover "API estimate excludes X% unpriced records." (`UsagePage.tsx:703-735`).
- Limits tab: one section per provider, one card per window: label, large `NN%` with "left" and a pace icon, bar on the right (`UsageLimitsPooled.tsx:530-569`). Multiple accounts are segments of one bar, same column across windows, ordered by next 5-hour refill; narrow screens show numbered legend rows (`:326-492`).
- Window row (single account, composer panel): `[label + "NN% left"] [bar 24px, pace tick] [pace icon + "resets in 3h 12m"]` as a 3-column grid (`UsageLimits.tsx:187-228`).
- Bars show remaining, not used. The pace tick marks where remaining would be under even spending (`paceRemainingPercent`, `usageLimits.ts:625-633`), drawn in a 6px transparent gap cut out of the bar, clamped 3px from each end, omitted when the bar is under 6px (`UsageLimits.tsx:77-113`).
- Hatched region at the end of a segment = what the next reset restores (`UsageLimitsPooled.tsx:374-383`).
- Segment popover rows: Plan, Signed in / Via, Left, Resets (`formatUpcomingTimestamp` plus "in 3h 12m"), Even pace ("38% left by now"), Restores ("+12% of pool") (`:135-216`). Hover opens it; one shared popover moves between segments.
- Cursor cards carry a description line under the label (`usageLimits.ts:116-132`).

Wording to borrow:
- Pace: "Ahead of pace: spending faster than the window elapses" / "On pace with the window" / "Under pace: headroom left for the rest of the window"; tooltip "The line is where even spending would be." (`UsageLimits.tsx:44-48, 173`).
- Pace rule (Tokei already matches): used% minus elapsed% greater than 5 is ahead, below -5 is under (`usageLimits.ts:635-645`).
- Durations: `3d 4h`, `2h 5m`, `7m` (`formatDuration`, `:647-655`); `resets in 3d 4h`, `resets now`, `Resets momentarily` under one minute (`:657-663`); compact `↻ 3h 12m` and a ticket glyph with the banked-credit count.
- Cursor: "Overall - Combined usage across both allowances, not a third quota." / "Cursor Models - Grok and Composer use this first. Auto can use either pool." / "Other Models - Claude, GPT, and Gemini use this pool. Grok and Composer fall back here."
- Cost: "Premium $X" for tier cost; "N tokens have no known price"; "Unpriced" instead of $0; "Per 1M tokens"; "Cache hit NN%" (`UsageModelDialog.tsx:61-64, 138-157`).

States:
- Loading / refreshing: per environment `inactive` (disconnected or errored), `loading`, `stale` (refreshing), `partway` (some providers answered, others `refreshing`), `ready` (`usageProgress.ts:11-37`). Labels: "Updating…", "Updating Codex…", "Updating 3 providers…" (`:39-71`). Figures dim to 40% opacity after a 150 ms delay so fast refreshes do not flicker (`UsagePage.tsx:1229-1231`). Dimmed only if nothing has answered yet.
- Limits probe results: no windows at all: "No provider on the selected environments reports subscription limits." (`UsageLimitsPooled.tsx:625-629`). `unsupported`: "This account has no subscription limits." `probeFailed`: "Could not read limits." Empty: "No limits reported." Notices render in one warning alert (`:687-699`, `usageLimits.ts:596-604`).
- Failed refresh after a good one: bars stay and a line says "<env> could not refresh limits. Showing the last known values." (`apps/mobile/.../UsageLimitsPooled.tsx:509-512`). Rule behind it: a failed probe never replaces a good reading (`provider-core/.../usageLimits.ts:107-109`).
- Cadence: opening Limits triggers a check; each client waits at least 5 minutes between automatic checks per environment, including after a failure; manual Refresh bypasses (`docs/user/usage.md`; `apps/mobile/.../usageLimitsRefresh.ts:39-45`). Same 5 minutes as Tokei.
- Widget: readings expire at the earlier of 15 minutes and the next reset; expired shows "Open T3 to refresh" and no bars (`subscriptionUsageSnapshot.ts:21-23, 78-120`).

Codex window mapping detail worth checking in Tokei (`codexUsageLimits.ts:63-98`): when `windowDurationMins` is missing, T3 assumes primary = 5 h and secondary = 7 d, or primary = 30 d for plans `free`/`go`; Tokei drops a window without a duration (`CodexRateLimitClient.swift:216-221`). T3 also skips any snapshot whose `limitId` is set and not `"codex"` (model-specific limits such as Spark); Tokei requires `limitId == "codex"`, same effect. Unverified whether the live app-server still omits durations; I did not run `codex app-server`.
