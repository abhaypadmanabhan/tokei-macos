## Outcome

Tokei 0.9.0 is released and installed. The numbers it shows are now right: sessions
that ran through Claude Code's nested subagents were never being counted, one session
that existed under two account directories was counted twice, and a message whose token
count grew as it streamed kept its first, smaller value — all fixed, and confirmed by an
independent recount of the full log history for both accounts. Codex no longer counts
repeated telemetry snapshots as new usage, Cursor's "accepted lines" no longer leak into
token charts, and opencode's most recent rows are no longer missed.

The app is dramatically lighter: peak memory on the same machine fell from about 7.7 GB
to 645 MB and steady-state memory from 3 GB to about 300 MB, with less CPU per refresh.

Accounts are now a first-class idea for any provider, not just Claude: every account has a
stable identifier, its own quota state and a launch selector, so an agent asking Tokei
"who has room?" gets an answer that distinguishes two Claude logins — or two Codex
logins — instead of one blended number. The agent-facing MCP was hardened along the way.

The interface lost about 1,400 lines of duplicate and decorative chrome, live figures now
roll smoothly when they change (and snap when Reduce Motion is on), and labels say what
the numbers actually are ("Last 7 days", "incl. cache").

Every change was reviewed by a second, independent agent before it merged; a security
review found nothing critical or high, and the medium/low items were fixed before
release. The notarized build is on GitHub, existing installs will be offered the update,
and the website reflects 0.9.0.
